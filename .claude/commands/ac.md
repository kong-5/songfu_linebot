# 執行規則

用 `.claude/agentic-gates.json` 定義的七步流程處理上面這項任務。**逐步做，不要一次做完再回報。**

每一步固定三件事：

1. 做這一步的工作。
2. 跑這一步的閘門：`npm run verify -- <階段 id>`（自動檢查）＋ 逐條回答該階段的 `manual` 清單。
3. 用下面的格式回報，**沒過就別進下一步**。

```
[步驟 N／7 <名稱>]
自動：✅/❌ 逐項列出（失敗要貼關鍵輸出）
人工：逐條回答 manual 清單，寫出「答案」不是「有做」
判定：通過 / 未通過（未通過寫出要回到哪一步補什麼）
```

`gate` 是 `human` 或 `both` 的步驟（1 釐清需求、2 探勘定位、3 擬定計畫、6 自我審查、7 交付），
**要等使用者回覆確認才往下**；`gate` 是 `auto` 的步驟自動檢查全綠即可自行往下。

任一 `manual` 條目使用者沒指定過標準時，**先提出你建議的驗收標準問使用者要不要照用**，不要自己默默定。

# 留檔

流程開始時建 `docs/agentic-runs/<YYYY-MM-DD>-<任務短名>.md`（範本見 `docs/agentic-runs/_範本.md`），
每步驗證完把結果寫進去：跑 `npm run verify -- <階段 id> --log docs/agentic-runs/<檔名>.md` 會自動附加自動檢查結果，
人工確認的答案自己補寫上去。這份紀錄跟著本次 PR 一起提交。

# 這個專案的硬規則（違反就是這一步沒過）

- 動任何功能前先讀 `CLAUDE.md`，相關細節再讀 `docs/` 對應文件。
- 改的是 `dist/`（實際執行碼），不是 `src/`。
- 新增表／欄位要同時改 `initSqlite` 與 `initPg`；SQL 一律可攜或 isPg 雙分支。
- 寫入類改動必須有：交易原子性、冪等性、稽核軌跡。
- 每次改動附帶對應 smoke test。
- 錯誤訊息要告訴使用者怎麼修正。
- Cloud Run `--max-instances=1` 是不變式，不准為了效能拿掉。
