## 二、本輪已修復（全部附在同一 PR）

### A. 交易原子性（守則 #2）
1. **LIFF 掃碼綁條碼**（`dist/liff/index.js` /api/scan/bind）：先刪後插包交易——舊版兩句之間失敗會把既有綁定刪掉沒補回。admin 端雙胞胎早就包了，這是漏網的第三份。
2. **空籃刪除整天**（admin/index.js /baskets/delete-day）：刪分項/歸零總計/寫 history 三步包交易，history 不再吞錯。
3. **盤點複盤改實盤數**（inventory.js /inventory/count-edit）：主 UPDATE＋audit INSERT 包交易——不再有「數字被改卻無舊值紀錄」。
4. **批發行情快照**（lib/wholesale-snapshot.js）：DELETE＋逐筆 INSERT 包交易——不再有「當日行情已刪未補」的半套資料。
5. **報價月報建立/刪除**（lib/quote-report.js）：主檔＋整份品項包交易——不再產生「只有前 N 項」且重按補不回來的月報。
6. **LINE 線上刪項/改量**（webhook/line.js）：DELETE/UPDATE＋order_item_edits 軌跡包交易（軌跡 rethrow）——軌跡寫失敗改走 Cloud Tasks 重試閉環，杜絕「客戶取消的品項被結單 rebuild 重建回來照樣出貨」。

### B. 冪等（守則 #2）
7. **手動新增客訴取號**（/complaints/new）：改走 `getNextOrderNoAdmin` 原子取號——舊版自刻「讀最大值+1」會併發撞號。
8. **POST /alias**：全域與客戶專用俗名都先查重——重按表單不再長出同名多列（resolve 取值不定的根源）。
9. **CSV 匯入客戶**（/import-customers）：整份包交易＋**LINE 群組唯一性守衛**——已綁其他客戶的群組直接跳過並在結果列出（舊版可直接蓋走，正是 2026-07-08「同群組不可綁兩客戶」防的事故）。

### C. 稽核軌跡（守則 #3）
10. 收款登記 /cash/collect 補 logDataChange（舊版「誰取消查得到、誰收錢查不到」）。
11. 手動入帳 /cash/extra-income 新增＋刪除補稽核（刪除先快照）。
12. 客戶硬刪（7 張表）與品項硬刪（6 張表）補稽核（先快照主檔）。
13. /import-customers 批次寫入補稽核；客戶專用別名建立補稽核。

### D. SQLite ↔ PG 雙寫（「本機全綠、雲端才炸」類）
14. **教育訓練月份排序**（training.js ×3 端點）：`CAST(month AS INTEGER)` 對自由文字（「3月」「Q1」）在 PG 直接 500——改 JS 端排序，本輪最可能已在雲端觸發的一條。
15. **PG 遷移健壯性**（db/index.js）：`DROP CONSTRAINT` 補 `IF EXISTS` ×2；`stocktake_expiry_item` 主鍵遷移補 BEGIN/COMMIT（比照三個兄弟遷移）。
16. **sqlForPg fail-fast 黑名單補洞**：`datetime(x,'+8h')` 兩參數形式／`date(?,'-3 day')`／IFNULL／julianday／printf 過去「不轉換也不擋」；另加**字串常值內 ? 護欄**（逐字元判斷、'' 跳脫也認得——placeholder 錯位是「不報錯只查錯資料」級的地雷）。
17. **客訴詳情頁日期查詢**改 isPg 前置分支——舊版靠「先讓 PG 報錯再 .catch 補救」，每開一次頁 PG 記一筆錯誤，且搬進交易會毒化整個交易。
18. `db/init.js` 補 await（PG 模式下舊版沒等 schema 建完就 exit 0）。
19. LIFF 客戶搜尋 LIKE 跳脫改「刪除萬用字元」（SQLite LIKE 沒有預設 ESCAPE，`\_` 會誤配）；cash 客戶搜尋路線欄補 LOWER（三欄大小寫行為一致）。

### E. XSS
20. **反射型 XSS ×2（高）**：`/admin/import?ok=`（未跳脫直出）與 `/admin/cash/collect?route=`（`JSON.stringify` 進 `<script>` 沒補 `<`，`</script>` 可逃逸）。
21. **DOM XSS ×4（中）**：品項搜尋下拉（review/訂單明細/品項挑選器/AI 範例）品名/料號/條碼進 innerHTML 未跳脫——補齊。
22. 防呆：training.js `delBtn` confirmMsg 補 escJsStr 級跳脫；inventory 統計頁 whJson 補 `<`（與同檔其他三處一致）。

### F. 基礎設施（防回歸的結構性槓桿）
23. **repo 級 eslint 正確性閘門**：新增 `.eslintrc.json`（no-undef/no-dupe-keys/no-unreachable 等 11 條正確性規則）＋ `npm run lint`（全 dist+test+scripts 約 4 秒）＋ **cloudbuild 部署前硬閘門**——dist 直接手改 JS 沒有編譯期檢查，打錯變數名過去要到執行期才爆。
24. smoke test：`test/health-check-20260727.test.js`（fail-fast 護欄／alias 冪等／客訴取號／匯入群組守衛／XSS 回歸／月報冪等）。

- **/orders/:orderId/apply-raw-text**：rebuild 交易成功後另一句 UPDATE raw_message 在交易外，失敗會讓人工更正被下次 rebuild 默默還原（要把 raw_message 更新併入 lib 的交易）。
- **稽核缺漏其餘項**：move-items／split-by-sub-customer／items/add／apply-raw-text／/import（品項）——訂單域拆檔時一併補。

### 中優先
- `basket-log.js`：getOrCreate 主列在交易外、history 快照吞錯。
- `rhythm-analysis.js`：當日訊號 DELETE＋迴圈 INSERT 無交易。
- training「計畫項目轉課程」無已轉守衛（重按多課程）；quote sort_order MAX+1 race；品項新增後 display_order 全表重編 race。
- LINE「刪第N項」位置定位在租約接手重跑時可能刪錯項（位置漂移）——可改成軌跡查重或以品項 id 定位。
- `daily_inventory.items` JSONB(PG) vs TEXT(SQLite)、`log_date` DATE vs TEXT、`claimed_at` 型別自相矛盾、`group_features` 遷移時間字串格式兩邊不同——新代碼要踩才會爆，改 schema 成本高，先記錄。
- admin 全域搜尋／LIFF 搜尋英數代號 LIKE 大小寫（PG 分、SQLite 不分）；pg numeric(oid 1700) 未設 type parser（現有使用點都有 Number() 包裹）。

### 低優先
- `escapeAttr` 進 inline JS 單引號字串未配 escJsStr 的存量點（員工/ERP 來源）；liff order-review 屬性未跳脫（日期/UUID）。
- `sqlForPg` 每次執行重跑正則（可加 LRU 快取）；`markets.map(fetchMarket)` 的 index 誤餵地雷。
- `package.json` 的 `dev` script 指向不存在的 `src/index.ts`（歷史殘留，可刪或改指 dist）。

## 四、健檢方法備忘（下次照抄）

1. 漏 await：AST 全量（acorn）比 grep 準——本輪 1146 個 db 呼叫 1141 有 await、5 個良性，**零漏 await**（上一輪體檢的成果保持住了）。
2. 雙寫：initSqlite vs initPg 表/索引/複合主鍵**清單已完全同步**，漂移都在型別層與遷移健壯性層。
3. 週期性把這五路掃描重跑一次（建議每月或每次大改後），加上 `npm run lint`＋`npm test`＋PG 冒煙三道 CI 閘門，是目前性價比最高的防 BUG 組合。
