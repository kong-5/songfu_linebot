# 體質健檢 — 2026-09-01（系統面與結構面）

承 `docs/體質健檢-2026-07-27.md`。這次是**系統面／結構面**的全面盤查：
安全、寫入三鐵律（交易／冪等／稽核）、結構與測試覆蓋、依賴健康。

**總評**：核心骨架其實相當紮實——三處 secret 比對都做了 timing-safe、機器端點與 webhook
都是 fail-closed、密碼 pbkdf2 加鹽、SQL 全參數化（掃遍全庫零注入命中）、`sqlForPg` 的
fail-fast 護欄執行得最徹底、金絲雀部署與 PG 冒煙閘門也很成熟。問題集中在三處：
**repo 裡躺著正式客戶資料**、**三鐵律的實際執行率遠低於規範宣稱**、**幾個病態大檔**。

### 2. 盤點 LIFF API 授權（P0）

舊版 `stkAuth` 只驗 ID Token 有效 ＝ 任何有 LINE 帳號的人，只要知道 LIFF ID
（寫死在原始碼、也印在每張 `#盤點` 卡片上）就能讀全倉庫存量、匯出整份條碼對照表、
**送出假盤點數字、改寫條碼→料號對應**。盤點已是主力業務，被污染不易察覺。

改為三條路任一通過，細節見 CLAUDE.md「LINE 盤點系統」段與 `dist/lib/stocktake-access.js`。
設計取捨都寫在該檔開頭（為什麼不直接強制員工綁定、為什麼需要授權記憶表、
為什麼 LINE API 失敗要 fail-open）。

### 3. 稽核軌跡（守則 #3）

體檢時全庫 **181 個寫入路由中約 86 個沒有任何稽核**。三套各自為政的實作
（admin `logDataChange`、liff `logFromLiff`、line.js 六處內嵌 INSERT）是根因——
「稽核要進交易」這種改動得各補一遍，實務上永遠補不齊。

**已做**：
- 收斂成 `dist/lib/audit.js` 單一權威。`writeAudit(h,…)` 失敗會 throw（交易內用），
  `writeAuditSafe(db,…)` 失敗只記 log（相容舊呼叫處）。呼叫端簽章零改動。
- 補上四條最關鍵的路徑，且**稽核與主寫入同交易**：
  - `POST /orders/:id/items`（後台改單最常用，過去逐項 UPDATE、無交易、零稽核）
  - `POST /orders/:id/items/add`（另加一次性 token 防重送）
  - `submitStocktake`（含被覆蓋的前一場次摘要）
  - 凌越 `callback` 的成功回填與單號衝突

### 4. 安全補強

- **登入節流的 XFF 繞過**：舊版 key 取 `X-Forwarded-For` 第一段（用戶端自填），
  且 `size>1000` 就整個 `clear()`——兩個一起用等於沒有節流。改成取最後一段
  ＋ 另開一條「只看帳號、不看 IP」的計數 ＋ 淘汰最舊的一成。
- **CSRF**：全站沒有 token，唯一防線是 `SameSite=Lax`（擋不住 GET 型破壞性操作，
  而系統確實有 GET+`/delete` 的模式）。加同源檢查覆蓋所有既有表單、不用改任何一頁；
  沒有 Origin/Referer 的非瀏覽器客戶端（內網代理、curl）刻意放行。
- **錯誤細節外流**：`lingyue-writeback`／`cash` 共 17 處把 `String(e.message)` 回前端。
  問題不在說太多而在說錯東西（SQL 片段、PG 索引名）。改用 `safeErrDetail(e)` 分流：
  資料庫內部訊息換掉、可讀的商業訊息保留（一併消音才真的違反守則 #4）。
- **xlsx CVE**：`0.18.5` 中 CVE-2023-30533（prototype pollution）與 CVE-2024-22363。
  觸發面只有一處（後台匯入，admin 認證後），但 pollution 是 process-wide 而同一個
  process 還在跑 LINE webhook → 加 `dist/lib/xlsx-safe.js` 污染偵測。

### E. 其他安全項（風險中低）

- session 無法撤銷：無狀態 HMAC token，改密碼/被竊後 7 天內持續有效。
  建議 payload 加 `pv`（password version），改密碼時遞增。
- 無 helmet／CSP／HSTS／X-Frame-Options。
- `/health` 對外吐 `dbError` 原文。
- `GET /admin/setup` 在 `admin_users` 為空時任何人可建第一個經理帳號（建議加 `SETUP_TOKEN`）。
- `ALLOW_UNAUTH_JOBS=1` 逃生門建議直接移除（確認 Cloud Run 沒設）。
- 員工綁定 token 走 query string，會進 access log（建議改 POST body）。
- pbkdf2 100k 次對 2026 年偏弱（可提高迭代或換 scrypt/argon2）；密碼下限 4 碼偏低。

### F. 前端

- `scan.html`（862 行 inline script）的掃碼函式組與 `admin/index.js:1654-1867`
  `barcodeAddModalHtml` **高度重複**（同名 `gotBarcode`/`hitBarcode`/`camManual`），
  是本 repo 最大的一處前後端重複。
- LIFF HTML 的設定注入靠 `replace` 整行 LIFF SDK script tag
  （`inventory.js:3621`、`liff/index.js:61-84`）——**那行字元動一個就靜默失效**。
  建議改 placeholder 註解（`<!--SF_BOOT-->`）＋ assert 替換確實發生。
