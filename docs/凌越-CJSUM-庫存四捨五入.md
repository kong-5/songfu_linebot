# 凌越銷貨單 CJSUM 四捨五入 — 症狀、證據與驗收方法

**症狀**：銷貨單金額／數量都對，但**庫存被扣錯**——扣的是四捨五入後的整數。
最後更新：2026-08-03

---

## 1. 兩個數量欄位

凌越銷貨單（資料種類 `0000A1`）明細裡有兩個數量：

| 欄位 | 意義 | 狀況 |
|---|---|---|
| `SD_QTY` | 單據數量（寺岡秤的實際重量，如 `4.3`） | ✅ 正確 |
| `CJSUM` | **實際扣庫存的數量**（如 `4`） | ❌ 被四捨五入 |

2026-07-21 那批單的實際數字（`庫存差 = SD_QTY − CJSUM`）：

```
料號        品名           SD_QTY   CJSUM   庫存差
FT1        南瓜             4.3      4      +0.3
SA9        進口白蘿蔔        1.8      2      −0.2
LB1        小白菜           3.5      4      −0.5
SG6        蒜仁(台灣)       0.5      1      −0.5
10400013   金針菇(真空)     1.4      1      +0.4
LA1        高麗菜          54.8     55      −0.2
C0100065   四角方籃           0      1      −1
```

全部符合 **round-half-up**（`.5` 一律進位）。但**四角方籃那行 `SD_QTY=0` 卻 `CJSUM=1`**
——0 四捨五入不會變成 1，代表 **`CJSUM` 不是由 `SD_QTY` 算出來的，是另一支邏輯自己填的**。
這就是「單據對、庫存錯」的根本原因：兩個數字由兩條路徑寫入。

## 2. 不是我們寫錯的

- 訂單回寫 `ly_writeback_bridge.py` 只送 `OD_QTY` 原值，沒有任何取整。
- 庫存推送 `ly_stock_push.py` 只是把 `SK_NOWQTY` 讀回來，不動數字。
- 雲端單位換算 `dist/lib/unit-conversion.js` 最多留到小數 3 位，也沒有整數化。
- 反推也成立：若是我們送錯，`SD_QTY` 也會是整數——但它是對的。

## 3. 為什麼要在意（＝盤差的來源之一）

殘量方向不固定（`4.3→4` 少扣 0.3、`1.8→2` 多扣 0.2），**不會互相抵銷**，會永久留在
庫存上。秤重品那種固定 ±0.3～0.5 的小盤差、天天出現又刪不掉的，有一部分就是這個，
**不是倉庫的人數錯**。

## 4. 驗收腳本（唯讀）

`scripts/ly_check_cjsum.py`——逐張撈當天銷貨單明細，比對 `SD_QTY` vs `CJSUM`。
**要跑在能連凌越 LAN 的那台 Windows**（`D:\Work\lystk_tool` 旁，或「凌越整合代理」資料夾）。

```bash
python ly_check_cjsum.py                       # 今天（松富 00），只列有差的行
python ly_check_cjsum.py --date 2026-08-03      # 指定日期
python ly_check_cjsum.py --icpno 02             # 松揚（01 龍港、03 松成）
python ly_check_cjsum.py --prefix A             # 只看寺岡/EDI 回轉的 A 開頭單
python ly_check_cjsum.py --doc A202608030001    # 只查一張
python ly_check_cjsum.py --json d:\cjsum.json   # 存檔給廠商
python ly_check_cjsum.py --selftest             # 不連凌越，驗算比對邏輯
```

結論怎麼讀：

- `✅ N 行全部相符` → 這個範圍沒有四捨五入，修好了。
- `❌ … 還沒修好` → 整段輸出貼給廠商（含單號＋料號＋兩個數字＋逐料號淨差）。
- `⚠ 明細裡完全沒有 CJSUM 欄位` → 欄位可能被改名：`--fields` 印出明細全部欄位名，
  再 `--cj-field <新欄位名>` 重跑。

冒煙測試：`test/ly-check-cjsum.test.js`（有 python 才跑，沒有就跳過，不擋 `npm test`）。

## 5. 廠商說「改好了」但還是四捨五入 — 要追問的四件事

1. **改的是哪一支？** 從四角方籃那行看，扣庫存是獨立邏輯；只調銷貨單的小數位處理沒用。
2. **client 端更新了嗎？** 凌越是 client-server，每台操作端各有 exe。現場拋轉／
   178go EDI 回轉那台若沒更新，照樣寫舊值。
3. **是設定不是程式？** 貨品主檔／單位的「數量小數位數」若為 0 位、或該品項被設成
   論件（`IS_PACK`），庫存還是整數。這些都是秤重品，要確認小數位。
4. **只改了一家公司別？** `00` 松富改了、`02` 松揚／`01`／`03` 可能沒改。

⚠ **已開出的單不會回溯**：驗收一定要看 patch 之後「新開＋新過帳」的單，
拿舊單截圖去對會被打回票（2026-07-21 那批就是舊單）。
